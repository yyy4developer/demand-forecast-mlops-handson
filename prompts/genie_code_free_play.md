# Genie Code に投げるプロンプト — 自由時間（`99_your_own_data`）

⭐ **自分のデータで、Genie Code に自然言語で頼んで作らせます。**
⚠️ 手でコードを書き直すことが目的ではありません。

## ⭐⭐ メインはこの 4 つ

| | 内容 |
|---|---|
| ⓪ | データを理解させる |
| ① | ⭐ **ダッシュボードを作る** |
| ② | メタデータ + メトリクスビュー（③ の前提） |
| ③ | ⭐ **Genie Agent を作る** |

⚠️ **④ 以降はおまけです。** 時間が余った人だけどうぞ。全部やる必要はありません。

> ⭐ `<TABLE>` は自分のテーブル名に置き換えてください（notebook が出力します）。
> 例: `demand_forecast_handson.fc_ws_taro_yamada.my_shipments`

> ⚠️⚠️ **一度に全部頼まないでください。** ① から順に、1 つずつ。
> ⭐ Genie Code は**質問してきます**。それに答えるのがこの時間の体験です。

---

## ⓪ まずデータを理解させる（これを最初にやると精度が上がります）

```
テーブル <TABLE> の中身を調べて、次を教えてください。

- 各列の意味の推測と、欠損・重複の有無
- 系列（品目 × チャネル）の数と、1 系列あたりの月数の分布
- 数量の分布（ゼロが多い系列があるか）
- ⭐ 需要の性質で系列を分類してください
  （毎月安定 / 数量が振れる / 出ない月がある）

結果は表で見せてください。
```

⭐ **`08` でやった「系列プロファイリング」を自分のデータでやることになります。**
⚠️ ここで「出ない月がある系列が多い」と分かったら、後の予測で効いてきます。

---

## ① ダッシュボードを作る（`01` に相当）

```
<TABLE> を使って AI/BI ダッシュボードを作ってください。

- 上部に KPI: 総数量 / 系列数 / 直近月の数量
- 月ごとの数量推移（折れ線）
- カテゴリ別の数量（棒）— カテゴリに使える列が無ければ品目上位 10 件で
- 数量上位の系列の表

タイトルと軸ラベルは日本語にしてください。
```

⚠️ 列名が日本語のときは、⭐ **バッククォートで囲む必要がある**ことを Genie Code に伝えてください。

---

## ② メタデータを付ける（`02` の前準備 = 精度の決め手）

```
<TABLE> に、Genie Agent が正しく答えられるようメタデータを付けてください。

- テーブルと全列に日本語のコメントを付ける
- 数量・年月・品目・チャネルに相当する列が何かを明示する
- ⭐ メトリクスビューを 1 つ作ってください
  - 軸: 年月 / 品目 / チャネル
  - 指標: 合計数量 / 月平均数量 / 系列数
```

⭐⭐ **`02` でいちばん強調した「Unity Catalog を整えてから Genie を作る」を自分でやります。**

---

## ③ Genie Agent を作る（`02` に相当）

```
② で作ったメトリクスビューを使う Genie Agent を作ってください。

- 渡すのはメトリクスビューだけにする（生テーブルは渡さない）
- 指示: 回答は日本語 / 数量は整数 / 比率は小数第 1 位まで
- 動作確認用に、業務で聞きたくなる質問を 5 つ提案してください
```

⚠️ **メトリクスビューが無いと作成に失敗します**（テーブルの実在を検証する API のため）。

---

# ⚠️ ここから下はおまけ

⭐ **④ 以降は時間が余った人向け**です。⚠️ メイン（⓪〜③）が終わっていれば十分です。

## ④ SQL 1 文で予測する（`03` に相当）

```
<TABLE> に対して ai_forecast() で 12 か月先まで予測する SQL を書いてください。

- 系列は品目 × チャネル（group_col）
- 月次
- ⚠️ horizon は「何期先」ではなく終端の日付で渡すこと
- ⚠️ frequency は 'ME'
- SQL ウェアハウスで実行できる形にしてください

結果を可視化するグラフも作ってください。
```

⚠️ **ノートブックの計算資源では動きません。** ⭐ SQL エディタか SQL ウェアハウス経由で。

---

## ⑤ モデルを作って記録・登録する（`04` に相当）

```
<TABLE> で需要予測モデルを作ってください。

- ⭐ 特徴量は関数に切り出して、学習と推論で同じものを使えるようにする
  （ラグ 1/2/3/12 か月、移動平均、移動標準偏差、非ゼロ比率、月、通し番号）
- ⚠️ 移動平均は当月を含めない（答えを見ないようにする）
- 検証は直近 12 か月
- ⭐⭐ 「前年同月と同じ」というベースラインを先に計算し、必ず並べて比較する
- 条件を変えて 3 回学習し、MLflow に記録する
- いちばん良いものを Unity Catalog に登録して @champion を付ける
- MAE と MASE をタグに残す
```

⭐⭐ **「ベースラインを先に出す」を必ず入れてください。** ⚠️ これが無いとモデルの価値が測れません。

---

## ⑥ まとめて推論し、精度を記録する（`05` に相当）

```
@champion を名前で呼び出して、実績のある全期間の予測を作り直してください。

- 予測を <あなたのスキーマ>.my_forecast_model に書き出す
- ⭐ 予測と実績を突き合わせた評価テーブルも作る
  （誤差率と誤差個数の両方を持たせること）
- ⭐ ベースラインとモデルを需要の性質ごとに比較する表を作る
- グラフも作る: 予測 vs 実績の散布図 / 月ごとの誤差推移
```

⭐⭐ **誤差を「率」と「個数」の両方で持たせてください。** ⚠️ 率だけ見ると数量の少ない品目を過大に問題視します。

---

## ⑦ 再学習して、勝ったら入れ替える（`06` に相当）

```
再学習して本番と比較するノートブックを作ってください。

- 最新までのデータで学習し、新バージョンとして登録して @challenger を付ける
- ⚠️ 設定（ハイパーパラメータ）は今の @champion から引き継ぐ
  （データを新しくした効果だけを見たいので）
- ⭐ 両モデルを同じ検証データで実際に走らせて比較する
- ⭐ 判定は直近 3 か月で行う。基準を満たしたら @champion を付け替える
- 満たさなければ据え置き、その旨を出力する
```

⭐⭐ **「勝ったら入れ替える」であって「作り直したら入れ替える」ではない**ことを指示に入れてください。

---

## ⑧ 自動実行にする（`07` に相当）

```
⑥ と ⑦ を毎月自動で回すジョブを作ってください。

- タスク: データ取り込み → 再学習と昇格判定 → 推論と評価の更新
- ⭐ 新しいファイルが置かれたら動くトリガーを付ける
- ⚠️ 失敗したらメールが飛ぶようにする
- Databricks Asset Bundle の YAML としても書き出してください
```

⚠️ **ファイル到着トリガーは同名ファイルの上書きでは発火しません。** ⭐ 月ごとに別ファイル名にします。

---

## ⑨ 品目ごとに手法を選ぶ（`08` に相当）

```
<TABLE> の系列を性質で分類し、⭐ 系列ごとに向いている予測手法を割り当てる方針を
提案してください。

- 予測しやすい系列とそうでない系列に分ける
- ⚠️ 予測しにくい系列は「当てにいかない」選択肢も含めて検討する
  （前年同月そのまま / 平均 / ゼロ）
- どの系列にどの手法を当てたかが後から分かる形で記録する
```

⭐⭐ **「当てにいかない」という判断を選択肢に入れる**のが `08` の見せ場でした。

---

## ⚠️ うまくいかないときのコツ

| ⚠️ 症状 | ⭐ 対処 |
|---|---|
| 的が外れた答えが返る | ⭐ **1 つずつ頼む。** ①→②→③ の順を守る |
| 列の意味を誤解される | ⭐ **⓪ と ② を先にやる。** メタデータが効きます |
| 日本語の列名でエラー | ⚠️ **バッククォートで囲むよう指示する** |
| 月数が足りないと言われる | ⚠️ ラグ 12 か月を使うため **各系列 24 か月以上**必要。⭐ 足りなければ ④ の `ai_forecast` を試す |
| そもそもデータが汚い | ⭐ **⓪ の結果を Genie Code に見せて「まず整えて」と頼む** |

⭐ **うまくいかない過程こそ持ち帰る価値があります。** どこで詰まったかを覚えて帰ってください。
