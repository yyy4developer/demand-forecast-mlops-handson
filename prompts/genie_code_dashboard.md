# Genie Code に投げるプロンプト — ダッシュボード作成

`01_dashboard` で使います。⚠️ `<あなたのスキーマ>` は notebook の出力に置き換えてください。

> ⚠️ **一度に多くを頼むと的が外れます。** 1 ページずつ頼むのがコツです。

---

## ① 多角的な分析ページ

```
このダッシュボードにページを 1 つ追加し、
<あなたのスキーマ>.mv_demand メトリクスビューを使った分析グラフを追加してください。

- 月ごとの出荷数量の推移（折れ線）
- 品目カテゴリ別の出荷数量（棒）
- チャネル別の構成比（円）
- 品目カテゴリ別の月平均出荷数量（棒）

タイトルはすべて日本語にしてください。
```

## ② ⭐ 予測と実績を突き合わせるページ

```
ページを 1 つ追加し、予測と実績の比較を見られるようにしてください。

- <あなたのスキーマ>.fct_forecast_accuracy を使う
- 対象月ごとの平均誤差率の推移（折れ線）
- 品目ごとの平均誤差個数 上位 10 件（横棒）
- 需要分類ごとの平均誤差率と平均誤差個数を並べた表

⭐ 誤差率と誤差個数は必ず両方見せてください。
  数量の少ない品目は誤差率が大きく出るため、率だけ見ると判断を誤ります。
```

## ③ ⭐ 在庫の健全性を見るページ

```
ページを 1 つ追加し、在庫の状況を見られるようにしてください。

- <あなたのスキーマ>.fct_inventory と dim_lead_time と dim_item を使う
- 拠点別の月末在庫と安全在庫の比較（棒）
- 欠品が発生した品目の一覧（最新月）
- リードタイムが長い品目 上位 10 件（横棒）
```

⭐ ③ を作ると、現場からよく出るこの 4 つの問いに答えられる状態になります。

- 欠品が発生している製品は？
- 余剰在庫がある拠点は？
- 需要予測の精度は？
- リードタイムが最も長い品目は？

---

## ⚠️ うまくいかないときの直し方

| 症状 | 頼み直し方 |
|---|---|
| グラフが多すぎて読めない | 「グラフを 3 つに絞って、それぞれ大きくしてください」 |
| 軸が英語になる | 「軸ラベルと凡例を日本語にしてください」 |
| 数字が細かすぎる | 「数量は整数、比率は小数第 1 位に丸めてください」 |
| 意図と違う集計 | ⭐ 使ってほしいテーブル名と列名を**明示して**頼み直す |
| 期間が全期間になる | 「直近 24 か月に絞ってください」 |
